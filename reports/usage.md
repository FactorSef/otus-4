## 1. Создание сервера

**Пользователь:**

> Необходимо делать мини сервер на express + sqlite
>
> Сервер должен реализовать 2 crud операции:
> 1. CRUD для модели пользователя User(id, username, age)
> 2. CRUD для модели статьи Article (title, text, user)
>
> Сервер и все его зависимости должен находиться в директории server

**Claude:**

Проверил окружение: Node v26.5.0, npm 11.17.0. В Node 26 уже есть встроенный модуль `node:sqlite`, поэтому нативные пакеты вроде `better-sqlite3` собирать не придётся. Создал проект в `server/`, установил зависимости (`npm install`, 0 уязвимостей) и проверил все операции на временной базе.

Результаты проверки:

```
--create user
{"id":1,"username":"alice","age":30}
--dup
{"error":"username already exists"} 409
--bad
{"errors":["username must be a non-empty string","age must be a non-negative integer"]} 400
--patch
{"id":1,"username":"alice","age":31}
--article
{"id":1,"title":"Hello","text":"World","user":{"id":1,"username":"alice","age":31}}
--article bad user
{"errors":["user with id 99 does not exist"]} 400
--put article
{"id":1,"title":"Hi","text":"There","user":{"id":1,"username":"alice","age":31}}
--list
[{"id":1,"title":"Hi","text":"There","user":{"id":1,"username":"alice","age":31}}]
--delete user (cascade)
204
--articles after
[]
--404
{"error":"User not found"} 404
```

Итоговый ответ:

Сервер готов и находится в директории `server/`. Я запустил его на временной базе и прогнал все операции: создание, чтение, обновление и удаление для обеих моделей, а также ошибки 400, 404 и 409. Всё отработало как ожидалось.

**Запуск:**
```
cd server
npm install
npm start        # http://localhost:3000, порт можно поменять через PORT
```

**Структура:**
- `server/src/index.js` — приложение Express, разбор JSON, обработка ошибок
- `server/src/db.js` — подключение к SQLite и создание таблиц
- `server/src/routes/users.js` — CRUD для `User`
- `server/src/routes/articles.js` — CRUD для `Article`

**Эндпоинты** (одинаковые для `/users` и `/articles`):

| Метод | Путь | Действие |
|---|---|---|
| GET | `/users`, `/articles` | список (для статей есть фильтр `?user=1`) |
| GET | `/:id` | одна запись |
| POST | `/` | создание |
| PUT | `/:id` | полная замена |
| PATCH | `/:id` | частичное обновление |
| DELETE | `/:id` | удаление (ответ 204) |

**Примеры тел запросов:**
- User: `{"username": "alice", "age": 30}`
- Article: `{"title": "Hello", "text": "World", "user": 1}`

**Решения, которые я принял сам:**
- **Библиотека SQLite:** встроенный в Node модуль `node:sqlite`, а не пакеты `sqlite3` или `better-sqlite3`. Ничего не нужно собирать под Windows, единственная зависимость — `express`.
- **Поле `user` у статьи:** при записи передаётся id автора, а в ответе приходит объект автора: `"user": {"id": 1, "username": "alice", "age": 30}`.
- **Удаление пользователя:** вместе с пользователем удаляются все его статьи.
- **Уникальность `username`:** повторное имя возвращает ошибку 409.
- **Файл базы:** данные хранятся в `server/data.sqlite`. Он создаётся при первом запуске и добавлен в `.gitignore`.

## 2. Пользователи по умолчанию

**Пользователь:**

> Давай добавим 3х пользователей по умолчанию

**Claude:**

Добавил трёх пользователей по умолчанию в `server/src/db.js`:

| id | username | age |
|---|---|---|
| 1 | alice | 25 |
| 2 | bob | 30 |
| 3 | charlie | 35 |

Пользователи добавляются только если таблица `users` пустая. Проверка на временной базе:

```
first start:
[{"id":1,"username":"alice","age":25},{"id":2,"username":"bob","age":30},{"id":3,"username":"charlie","age":35}]
restart after deleting bob:
[{"id":1,"username":"alice","age":25},{"id":3,"username":"charlie","age":35}]
```

При первом запуске появились все трое, а после удаления `bob` и перезапуска он не вернулся.

**Важно:** если в `server/data.sqlite` уже есть пользователи, новые туда не попадут. Удалите этот файл, и при следующем запуске база создастся заново с тремя пользователями.

Если нужно, чтобы эти пользователи восстанавливались при каждом запуске, даже после удаления, это легко поменять.

## 3. Статьи по умолчанию

**Пользователь:**

> Давай добавим еще 6 статей по умолчанию.
> У alice это будут рецепты плова и супа
> У bob'a это 2 статьи по установке react.js
> У charle это 2 статьи про рыбалку и выбор спининга

**Claude:**

Добавил 6 статей по умолчанию в `server/src/db.js`. Проверка на чистой базе:

```
1 alice | Рецепт узбекского плова
2 alice | Рецепт куриного супа с лапшой
3 bob | Установка React.js с помощью Vite
4 bob | Установка React.js в существующий проект
5 charlie | Рыбалка для начинающих: с чего начать
6 charlie | Как выбрать спиннинг
```

Тексты статей написал я сам. Рецепты состоят из списка ингредиентов и пошаговой инструкции. Статьи про React — это команды для установки. У charlie статьи про основы рыбалки и про то, как выбрать спиннинг по длине, тесту, строю и материалу.

Как это работает:
- **Когда добавляются:** статьи создаются только если таблица статей пустая, так же как пользователи. В текущей `data.sqlite` они появятся при следующем запуске, если своих статей ещё не создавали. Удалять файл базы не нужно.
- **Привязка к авторам:** статья привязывается к автору по `username`, а не по id. Если кого-то из пользователей по умолчанию уже удалили, его статьи просто не создадутся, и сервер не упадёт.
