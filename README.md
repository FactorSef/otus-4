# Блог-API и LLM-агент

Решение состоит из двух частей:

- **`server/`** — REST API блога на Express и SQLite: пользователи и статьи. Запускается в Docker.
- **`agent/`** — консольный агент на LangChain.js. Понимает запросы на естественном языке и выполняет их через API сервера. В качестве LLM использует локальную модель Qwen в LM Studio.
- **`py-agent/`** — тот же агент на Python (LangChain + Pydantic): те же инструменты, промпт и формат ответа.

```
Пользователь ──► agent (LangChain) ──► LM Studio (Qwen)
                      │
                      └──► server (Express + SQLite, :3000)
```

## Что понадобится

| Компонент | Версия | Зачем |
|---|---|---|
| Docker Desktop | любая свежая | запуск сервера |
| Node.js | 22.13 или новее | запуск агента на JS |
| Python | 3.11 или новее | запуск агента на Python (по желанию) |
| LM Studio | с загруженной моделью `qwen/qwen3.6-35b-a3b` | LLM для агента |

Модель должна поддерживать вызов инструментов (tool calling). Qwen3 его поддерживает.

## Запуск

### 1. Сервер

Запустите Docker Desktop и выполните в корне репозитория:

```
docker compose up -d --build
```

Сервер поднимется на `http://localhost:3000`. Проверка:

```
curl http://localhost:3000/users
```

При первом запуске база заполняется тестовыми данными: пользователи `alice`, `bob`, `charlie` и по две статьи у каждого. База хранится в Docker-томе `server-data`, поэтому данные переживают перезапуск контейнера.

### 2. LM Studio

1. Загрузите модель `qwen/qwen3.6-35b-a3b` (вкладка **My Models** → **Load**).
2. Включите сервер: вкладка **Developer** → **Start Server**, или командой:

   ```
   lms server start
   ```

3. Проверьте, что модель видна по API:

   ```
   curl http://localhost:1234/v1/models
   ```

### 3. Агент

```
cd agent
npm install
npm start
```

Если LM Studio работает на другом адресе или вы используете другую модель, скопируйте `.env.example` в `.env` (`copy .env.example .env` в Windows) и раскомментируйте нужные строки.

**Python-версия** (нужен Python 3.11+):

```
cd py-agent
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m agent
```

Команды использования ниже одинаковы для обеих версий: вместо `npm start -- "запрос"` выполните `python -m agent "запрос"`. Подробнее — в [py-agent/README.md](py-agent/README.md).

## Использование агента

**Интерактивный режим:** выполните `npm start` и вводите запросы. Для выхода введите `exit`, `quit` или `выход`. Агент помнит историю диалога, пока процесс запущен.

**Один запрос:** передайте его аргументом:

```
npm start -- "покажи все статьи bob"
```

На каждый запрос агент возвращает JSON из трёх полей:

- `status` — `success` или `failed`;
- `action` — действие, которое просил пользователь: `create_user`, `get_article`, `list_articles`, `delete_user` и т. д.; `multiple` — несколько действий сразу, `unknown` — запрос не про API;
- `data` — результат: запись или список из API при успехе, `{ "reason": "..." }` при неудаче.

Перед ответом в stderr выводится каждое обращение к API: `→` — вызов инструмента с аргументами, `←` — ответ сервера. Ответ печатается в stdout, поэтому его можно сохранить отдельно: `npm start --silent -- "запрос" 2>nul > answer.json`.

```
> покажи статьи bob
  → list_entities({"entity":"user"})
  ← {"ok":true,"status":200,"result":[{"id":1,"username":"alice","age":25},{"id":2,"username":"bob","age":30},…
  → list_entities({"entity":"article","user_id":2})
  ← {"ok":true,"status":200,"result":[{"id":3,"title":"Установка React.js с помощью Vite",…
{
  "status": "success",
  "action": "list_articles",
  "data": [
    { "id": 3, "title": "Установка React.js с помощью Vite", "text": "…", "user": { "id": 2, "username": "bob", "age": 30 } },
    { "id": 4, "title": "Установка React.js в существующий проект", "text": "…", "user": { "id": 2, "username": "bob", "age": 30 } }
  ]
}

> удали пользователя charlie
{
  "status": "failed",
  "action": "delete_user",
  "data": { "reason": "Удаление пользователей недоступно. У меня нет такой операции." }
}
```

Подробнее о формате — в [agent/README.md](agent/README.md#формат-ответа).

### Примеры запросов

| Запрос | Что сделает агент |
|---|---|
| `покажи всех пользователей` | получит список пользователей |
| `создай пользователя dave, 28 лет` | создаст пользователя |
| `alice теперь 26 лет` | найдёт id alice и обновит только возраст |
| `напиши от имени charlie статью «Зимняя рыбалка» с текстом …` | найдёт id charlie и создаст статью |
| `покажи полный текст статьи про плов` | найдёт статью по заголовку и выведет её |
| `передай статью про спиннинг пользователю bob` | сменит автора статьи |

### Ограничения агента

- **Удаление недоступно.** Агент откажется удалять пользователей и статьи: такого инструмента у него нет. Удалить запись можно напрямую через API (см. ниже).
- Если в запросе не хватает данных (например, возраста нового пользователя), агент переспросит, а не придумает значение.
- На один запрос приходится не больше 15 вызовов инструментов, это защита от зацикливания.
- Локальная модель отвечает заметно медленнее облачной: запрос с несколькими вызовами инструментов может занимать минуту и больше.

## API сервера

Сервер можно использовать и напрямую, без агента.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/users` | список пользователей |
| `GET` | `/users/:id` | пользователь по id |
| `POST` | `/users` | создать: `{ "username": "dave", "age": 28 }` |
| `PUT` | `/users/:id` | полная замена |
| `PATCH` | `/users/:id` | частичное обновление |
| `DELETE` | `/users/:id` | удалить (вместе с его статьями) |
| `GET` | `/articles` | список статей; `?user=:id` — статьи одного автора |
| `GET` | `/articles/:id` | статья по id, автор приходит вложенным объектом |
| `POST` | `/articles` | создать: `{ "title": "…", "text": "…", "user": 1 }` |
| `PUT` | `/articles/:id` | полная замена |
| `PATCH` | `/articles/:id` | частичное обновление |
| `DELETE` | `/articles/:id` | удалить |

Коды ошибок: `400` — невалидные поля или несуществующий автор, `404` — запись не найдена, `409` — `username` уже занят.

## Настройки

**Агент** (`agent/.env`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_BASE_URL` | `http://localhost:1234/v1` | OpenAI-совместимый endpoint LM Studio |
| `LLM_MODEL` | `qwen/qwen3.6-35b-a3b` | id модели из `GET /v1/models` |
| `LLM_API_KEY` | `lm-studio` | ключ; LM Studio его не проверяет |
| `API_URL` | `http://localhost:3000` | адрес сервера блога |

**Сервер** (переменные окружения контейнера): `PORT` (по умолчанию `3000`) и `DB_PATH` (по умолчанию `/data/data.sqlite`).

## Остановка и сброс данных

```
docker compose down        # остановить сервер, данные сохранятся
docker compose down -v     # остановить и удалить базу; при следующем запуске она заполнится заново
```

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `failed to connect to the docker API` | Docker Desktop не запущен. Запустите его и повторите `docker compose up`. |
| `node: bad option: --env-file-if-exists` | Старая версия Node.js. Обновитесь до 22.13+ или запустите `npx -y node@22 src/index.js` из папки `agent`. |
| `Connection error` при запросе к агенту | Сервер LM Studio выключен. Выполните `lms server start`. |
| Агент сообщает, что API недоступен | Не запущен сервер блога. Проверьте `docker compose ps`. |
| Python-агент получает от сервера или LM Studio ошибку 503 | Запрос ушёл через системный прокси. Для `localhost` агент прокси уже не использует; если сервер на другом адресе, добавьте его в исключения прокси. |
| Модель не найдена | Модель не загружена в LM Studio или `LLM_MODEL` не совпадает с id из `/v1/models`. |

## Структура репозитория

```
docker-compose.yml   запуск сервера
server/              REST API (Express + node:sqlite)
  src/index.js       приложение и обработка ошибок
  src/db.js          схема БД и тестовые данные
  src/routes/        маршруты /users и /articles
agent/               LangChain-агент
  src/index.js       модель, агент, CLI
  src/tools.js       инструменты create/get/update/list
  src/prompt.js      системный промпт
  src/api.js         HTTP-клиент к серверу
py-agent/            тот же агент на Python
  agent/__main__.py  модель, агент, CLI
  agent/tools.py     инструменты create/get/update/list
  agent/prompt.py    системный промпт
  agent/response.py  схема ответа
  agent/api.py       HTTP-клиент к серверу
reports/             отчёты о ходе работы
```

Подробнее об агентах см. в [agent/README.md](agent/README.md) и [py-agent/README.md](py-agent/README.md).
